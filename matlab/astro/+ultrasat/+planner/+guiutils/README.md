# ULTRASAT Planner — Helper Classes

This folder contains helper classes that support the **ULTRASAT Planner GUI** and application logic.  
The helpers are designed to improve **code organization**, **robustness**, and **maintainability** by separating logic from the main AppDesigner file (`PlannerMain.mlapp`).

---

## MainModule Helpers

These helpers are **instantiated inside `MainModule`** and provide low-level, 
reusable functionality used throughout the Planner.

- **`GuiHelper.m`**  
  Provides GUI-related utility functions, such as handling modal dialogs, 
  formatting GUI elements, date/time formatting for display, and status coloring.

- **`TableHelper.m`**  
  Provides helper functions for working with MATLAB tables, including conversions 
  between datetime and string formats, column manipulation, and general table utilities.

Usage example:
```matlab
app.MainModule.GuiHelper.showModal(app, FormApp);
app.MainModule.TableHelper.convertTableDatetimeToString(Data);
```

---

## PlannerMain* Helpers

These helpers are **instantiated inside `PlannerMain.mlapp`** during application initialization.  
Each helper encapsulates a specific functional area of the Planner, replacing large 
method groups previously implemented directly inside the `.mlapp` file.

Example of initialization in `PlannerMain.init()`:
```matlab
app.BuildHelper = ultrasat.planner.guiutils.PlannerMainBuildHelper();
```

### List of PlannerMain Helpers

| Helper Class                               | Responsibility |
|--------------------------------------------|----------------|
| `PlannerMainApprovedTargetsHelper.m`       | Managing Approved Targets table and related operations |
| `PlannerMainBuildHelper.m`                 | Building plans according to plan type and showing build status |
| `PlannerMainNewPlanHelper.m`               | Creating new plans (HCS, LCS, DDT, AllSS, TOO) |
| `PlannerMainPlanParamsHelper.m`           | Handling Plan Parameters window and applying changes |
| `PlannerMainPlanTargetsHelper.m`          | Editing, displaying, and managing Plan Targets |
| `PlannerMainPlotHelper.m`                  | Plotting Sky Maps, Graphs, and CalibObj tables |
| `PlannerMainSessionHelper.m`               | Session-level functions such as login/logout |
| `PlannerMainStatusHelper.m`                | Managing application and plan status fields, read-only mode, modified flags |
| `PlannerMainStorageHelper.m`               | Loading, saving, duplicating, and closing plans (DB and file) |
| `PlannerMainSubmitHelper.m`                | Validation and submission of plans |
| `PlannerMainUniqueTargetsHelper.m`         | Managing Unique Targets (add/edit/delete/load/save) |

## Design Rationale

Originally, `PlannerMain.mlapp` contained over **5000 lines** of code, mixing GUI 
definitions, event callbacks, and application logic.  
This was refactored to:

- Move all functional logic into **dedicated helpers**.  
- Keep only **short event callbacks** and auto-generated GUI code inside `PlannerMain.mlapp`.  
- Improve **code readability**, **testability**, and **robustness** through clearer separation of responsibilities.

After refactoring, the `.mlapp` file was reduced to ~2600 lines, with most of the 
remaining code being GUI component definitions generated by AppDesigner.

---

## Error Handling

As part of the ongoing robustness improvements, helper functions are being updated 
to include consistent `try/catch` blocks, structured error logging, and user feedback 
through `msglog` and GUI dialogs.
